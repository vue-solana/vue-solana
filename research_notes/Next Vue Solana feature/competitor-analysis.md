# Competitor and adjacent Solana JavaScript framework analysis

Research date: 2026-11-21. Sources are primarily primary: npm registry metadata/API (`registry.npmjs.org`, `api.npmjs.org` last-month download counts), official GitHub repos via `api.github.com` (`pushed_at`, stars), and official READMEs via `raw.githubusercontent.com`. Web search was unavailable (HTTP 402/429), so all facts below were fetched directly from those primary endpoints. All download figures are "downloads last month" at research time; all `pushed_at` dates are GitHub repository default-branch pushes.

## 1. What does `@solana/react-hooks` expose, and which ergonomics are genuinely framework-agnostic?

### Takeaway

`@solana/react-hooks` (v1.4.1) is now explicitly **unmaintained**; its important legacy is the companion framework-agnostic `@solana/client` (v1.7.0, also unmaintained), whose store/actions/watchers/helpers model — not the React hooks themselves — is the transferable design. The maintained replacements are Anza's Kit plugins plus `@solana/react` v8.6.0, which preserve the same ideas with Kit-native capability typing.

### Cited Findings

- `@solana/react-hooks` latest is **1.4.1**, described as "React hooks for the @solana/client Solana client"; it depends on `@solana/client` **1.7.0**, `@solana/kit ^5.0.0`, `swr ^2.3.6`, and `zustand ^5.0.0`; **16,792** downloads last month — [npm registry](https://registry.npmjs.org/@solana/react-hooks/latest); [npm downloads API](https://api.npmjs.org/downloads/point/last-month/@solana%2freact-hooks).
- Its README opens with an explicit warning: "`@solana/react-hooks` is no longer maintained. Use `@solana/react` instead"; the repository-level README also warns framework-kit is no longer maintained and recommends Kit plugins, `@solana/react`, Kit, and web3.js v3 — [react-hooks README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/packages/react-hooks/README.md); [framework-kit README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/README.md).
- The `solana-foundation/framework-kit` repo has 87 stars and was last pushed **2026-11-01** (documentation/maintenance activity, not product development) — [GitHub API](https://api.github.com/repos/solana-foundation/framework-kit).
- Hook surface documented: `SolanaProvider`, `useWalletConnection` (connectors, connect/disconnect, status, currentConnector), `useBalance` (lamports + slot + fetching), `useAccount`, `useSolTransfer`, `useSplToken` (balance, owner, send, status, error, refresh, `tokenProgram: 'auto'` for Token-2022, decimal strings vs `amountInBaseUnits`), `useLookupTable`, `useNonceAccount`, `useTransactionPool` (instruction queue plus `prepare`/`send`/`sign`/`toWire`/`reset`, latest blockhash), `useSendTransaction`, `useWaitForSignature`, `useProgramAccounts` (via `SolanaQueryProvider`), `useSimulateTransaction`, `useWalletSession` — [react-hooks README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/packages/react-hooks/README.md).
- The framework-agnostic `@solana/client` v1.7.0 (last published **2026-01-16**, **61,129** downloads/month) offers: `createClient` with cluster monikers (`mainnet`, `devnet`, `testnet`, `localnet`, inferred WebSocket URLs), `autoDiscover()`/`filterByNames()` Wallet Standard connectors, a Zustand store with `serializeSolanaState`/`deserializeSolanaState`, `actions` (`connectWallet`, `fetchAccount`, `fetchBalance`, `fetchLookupTable(s)`, `fetchNonceAccount`, `setCluster`, `requestAirdrop`, `sendTransaction`), `watchers` (`watchAccount`, `watchBalance`, `watchSignature`, all returning `abort()`), and `helpers` (`solTransfer`, `splToken({mint, tokenProgram: 'auto'})`, `transaction.prepare/sign/toWire/send` with version `0` chosen automatically when lookup tables are used) — [@solana/client README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/packages/client/README.md); [npm metadata](https://registry.npmjs.org/@solana/client).
- `@solana/client`'s own README is also marked unmaintained and points to [Kit plugins](https://github.com/anza-xyz/kit-plugins) — [@solana/client README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/packages/client/README.md).
- The maintained successor `@solana/react` **8.6.0** (npm metadata modified **2026-11-20**, with 8.7.0 canaries same day; **130,517** downloads/month) ships `ClientProvider`, `useClient<T>()`, `useClientCapability`, `useAction`, `usePlanTransaction(s)`, `useSendTransaction(s)`, `useAirdrop`, `usePayer`, `useIdentity`, `useRequest`, `useSubscription`, `useTrackedData`, SWR and TanStack Query adapters, wallet-account signers, `useSignIn` and `useSelectedWalletAccount` — [npm registry](https://registry.npmjs.org/@solana/react); [npm downloads](https://api.npmjs.org/downloads/point/last-month/@solana%2freact); [React README](https://raw.githubusercontent.com/anza-xyz/kit/main/packages/react/README.md).
- `@solana/react` semantics worth translating: `useRequest` is stale-while-revalidate (`refresh()` keeps prior `data`/`error`, accepts per-attempt `AbortSignal` factory or override, `null` source = `disabled`); `useSubscription` exposes `reconnect()` and preserves stale data across errors; `useTrackedData` seeds a subscription with a one-shot RPC fetch and **slot-deduplicates** out-of-order arrivals; `useAction` supersedes in-flight calls by aborting the previous one and requires `isAbortError` filtering for awaiters — [React README](https://raw.githubusercontent.com/anza-xyz/kit/main/packages/react/README.md).

### Inferences

- Framework-agnostic ideas: one client/context per app; explicit capability detection; typed store + actions + watchers split; slot-aware freshness; abortable/superseded async actions; high-level "money" helpers (SOL/SPL transfer, airdrop); cluster moniker resolution; wallet discovery filters; optional persistence serialization. These map cleanly to Vue `provide/inject`, `ref`/`shallowRef`, `watch`, `onScopeDispose`, and composables.
- React-specific mechanics to avoid copying: provider-in-JSX, `useMemo`/`useCallback` identity requirements for sources, component unmount/StrictMode semantics, Suspense for async plugin clients, `'use client'` directives, and hook call-order rules. Vue equivalents are reactive refs/watchers and scope disposal, not manual memoization.
- `@solana/react` keeping only generic client/action/data hooks while delegating plugin-specific hooks to each plugin's `/react` subpath is an architectural signal: a framework library should be a thin reactive adapter over Kit capabilities, not a parallel RPC implementation.

### Gaps

- No evidence found that framework-kit's hooks were ever available outside React; only `@solana/client` is described as framework-agnostic.
- Exact deprecation dates are not in the READMEs; the "no longer maintained" warning is observable as of the research date, with the framework-kit repo last pushed 2026-11-01 and the last `@solana/client` release on 2026-01-16.

## 2. What does `gill` offer as a Kit wrapper, and which conveniences are worth considering versus duplicate-Kit or maintenance risk?

### Takeaway

`gill` is a real source of good high-level conveniences (one-call client, transaction builders, explorer/rent helpers, keypair loading, bundled program clients) but is a poor dependency choice in 2026: last release **2025-11-07**, last repo push **2026-03-14**, and pinned to Kit **^5** while current Kit is **8.6.0**. Borrow the ergonomics, not the package.

### Cited Findings

- `gill` latest **0.14.0**, published **2025-11-07** (repo `gillsdk/gill` last pushed **2026-03-14**, 414 stars, 54 open issues), **52,508** downloads/month — [npm metadata](https://registry.npmjs.org/gill); [GitHub API](https://api.github.com/repos/gillsdk/gill); [npm downloads](https://api.npmjs.org/downloads/point/last-month/gill).
- `gill` depends on `@solana/kit ^5.0.0` (current `@solana/kit` is 8.6.0, published 2026-10-28), plus bundled program clients `@solana-program/system`, `token-2022`, `compute-budget`, `address-lookup-table` — [npm registry](https://registry.npmjs.org/gill/latest); [npm @solana/kit](https://registry.npmjs.org/@solana/kit/latest).
- The repo README states all `@solana/kit` imports can be replaced by `gill` for "exact same functionality" plus extras; it publishes `gill`, `@gillsdk/react` (**0.7.0**, React hooks built on `@solana/react` + TanStack Query), and `@gillsdk/solana-pay` — [gill README](https://raw.githubusercontent.com/gillsdk/gill/master/README.md); [@gillsdk/react metadata](https://registry.npmjs.org/@gillsdk/react/latest).
- Documented extras: `createSolanaClient({ urlOrMoniker })` returning `{ rpc, rpcSubscriptions, sendAndConfirmTransaction }`; `createTransaction({ version, feePayer, instructions, latestBlockhash, computeUnitLimit, computeUnitPrice })`; `getExplorerLink`; minimum-rent calculation; node-only keypair loaders (`loadKeypairSignerFromFile`, `...FromEnvironment`, `...FromEnvironmentBase58`, defaulting to Solana CLI path); transaction builders for "create a token with metadata", "mint tokens", and "transfer tokens"; debug mode — [gill package README](https://raw.githubusercontent.com/gillsdk/gill/master/packages/gill/README.md).
- gill's own comparison page argues Kit "only ships low level primitives" and forces verbose boilerplate, whereas gill adds "lightly opinionated abstractions ... all from a single compatible interface" — [gill vs Kit docs](https://gillsdk.com/docs/compare/kit).
- Repo policy this analysis must respect: gill (and `@solana-commerce/solana-pay`) were removed from this project because gill carried a second Kit copy and broke example builds; `pnpm-workspace.yaml` overrides must match the single `@solana/kit` range — [AGENTS.md](./../../../../AGENTS.md) (repository handoff notes, read locally; not modified).

### Inferences

- Worth adopting as _ideas_ in a Kit-first Vue library: moniker-based client creation with safe defaults; an all-in-one helper bundle that still re-exports Kit; compute-budget-aware transaction creation; explorer-link and rent helpers; high-level token builders; developer "debug mode" that explains failed transactions.
- Not worth adopting as a dependency: gill's Kit v5 pin would create two `SolanaError` classes/subscription signals and maintenance risk; its React hooks are doubly indirect (`gill` -> `@gillsdk/react` -> `@solana/react`) and irrelevant to Vue.
- Several gill conveniences are already covered by Vue Solana (`createSolanaClient`, cluster resolution, airdrop, Solana Pay, token account reads); the genuine gap is _transaction_ ergonomics (compute-budget defaults, explorer links, simulation/debug) rather than another client layer.

### Gaps

- No source found quantifying how much of gill's 52k monthly downloads is genuine adoption versus transitive installs; the repo push gap of ~8 months is the clearest maintenance signal.

## 3. What do `@solana/wallet-adapter` / wallet UI libraries solve that a framework library may or may not need to solve?

### Takeaway

Wallet Adapter's durable value is wallet discovery/adapters, connection state, and ready-made selection UI for React; a Vue library needs the headless parts (discovery, connection, selected account, signing, errors) but should not import React modal patterns or web3.js v1 adapters.

### Cited Findings

- `@solana/wallet-adapter-react` latest **0.15.40** (**5,329,687** downloads/month) and `@solana/wallet-adapter-react-ui` latest **0.9.40** (**951,660** downloads/month) still peer-depend on **`@solana/web3.js ^1.99.0`** — [react metadata](https://registry.npmjs.org/@solana/wallet-adapter-react/latest); [UI metadata](https://registry.npmjs.org/@solana/wallet-adapter-react-ui/latest); [downloads](https://api.npmjs.org/downloads/point/last-month/@solana%2fwallet-adapter-react).
- Repo `anza-xyz/wallet-adapter`: 2,029 stars, last pushed **2026-10-06**, 45 open issues, not archived — [GitHub API](https://api.github.com/repos/anza-xyz/wallet-adapter).
- Its package layout is deliberately modular: `base` (adapter interfaces, errors, utilities), `react` (contexts/hooks), `react-ui` (CSS-only components), per-wallet adapter packages and an aggregate `wallets` package; the docs explicitly list **Vue** as a _community-maintained_ integration alongside Angular and Svelte — [PACKAGES.md](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/PACKAGES.md).
- The React UI package README itself is a stub ("Coming soon"), so the modal/button API is documented mainly through the demo/docs site — [react-ui README](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/README.md); [wallet-adapter docs](https://anza-xyz.github.io/wallet-adapter/).
- The maintained Kit path does **not** use wallet-adapter: `@solana/react` 8.6.0 depends directly on `@wallet-standard/react`, `@wallet-standard/ui`, `@wallet-standard/ui-registry`, `@solana/wallet-standard-features`; a Kit wallet plugin exists (`@solana/kit-plugin-wallet`, **26,416** downloads/month, plugins `walletSigner`, `walletIdentity`, `walletPayer`, `walletWithoutSigner`) — [@solana/react metadata](https://registry.npmjs.org/@solana/react/latest); [kit-plugins README](https://raw.githubusercontent.com/anza-xyz/kit-plugins/main/README.md); [downloads API](https://api.npmjs.org/downloads/point/last-month/@solana%2fkit-plugin-wallet).
- Vue Solana already implements the headless layer: wallet discovery list/selection/refresh, connect/disconnect, app-wide selected-wallet-account context, message/transaction/batch signers, SIWS, Wallet Standard signature verification, Android MWA and iOS browser wallets — [repository handoff notes](./../../../../AGENTS.md) (local file, read only).

### Inferences

- A framework library should solve: wallet-standard discovery and filtering, one active wallet across the app, connection status/reconnect, selected-account reactivity, signer construction, error normalization, and mobile/deep-link flows. All are UI-framework-neutral.
- Visual concerns (modal, multi-button, wallet icons, CSS) belong in a separate Vue component package or userland; the React component hierarchy (`WalletModalProvider`, `WalletMultiButton`) is framework-specific and not worth mirroring inside core composables.
- Wallet Adapter's huge download counts reflect its React/web3.js v1 legacy install base, not a reason to adopt its data model; the official successor stack has moved to Wallet Standard + Kit plugins.

### Gaps

- The official Wallet Adapter docs page was not fully parsable in this pass (UI package README is a stub), so exact modal behavior/feature list is inferred from package descriptions and demo references rather than a primary feature table.

## 4. What do `@solana-program/token` and Codama-generated clients make easy, and where is a Vue-specific reactive layer still useful?

### Takeaway

`@solana-program/token` and Codama v2 generate strongly typed, stateless instruction/account/PDA/error helpers that plug into a Kit client; Vue adds value by making those helpers reactive (wallet/address inputs, refresh, subscriptions, pending/confirmed transaction state) rather than by reimplementing them.

### Cited Findings

- `@solana-program/token` latest **0.18.0**, published **2026-10-16**, peer `@solana/kit ^8.5.0`, **10,534,618** downloads/month; repo `solana-program/token` has 213 stars, last pushed **2026-11-20**, 478 commits, and generates its JS client from a checked-in `idl.json` using Codama — [npm metadata](https://registry.npmjs.org/@solana-program/token); [downloads](https://api.npmjs.org/downloads/point/last-month/@solana%2fprogram%2ftoken); [GitHub API](https://api.github.com/repos/solana-program/token); [repo README](https://raw.githubusercontent.com/solana-program/token/main/README.md).
- The token JS client exports generated code plus explicit high-level helpers: `tokenProgram`/`TokenPlugin`, batch instructions, `createMint`, `mintToATA`, `transferToATA`, `assertValidTokenTransferDestination` — [clients/js/src/index.ts](https://raw.githubusercontent.com/solana-program/token/main/clients/js/src/index.ts).
- `codama` latest **1.11.0**, **283,432** downloads/month; repo `codama-idl/codama` has 476 stars, last pushed **2026-11-19** — [npm metadata](https://registry.npmjs.org/codama/latest); [downloads](https://api.npmjs.org/downloads/point/last-month/codama); [GitHub API](https://api.github.com/repos/codama-idl/codama).
- `@codama/renderers-js` (Anza-maintained) generates typed helpers for accounts, instructions, PDAs, defined types, errors, and events, plus a Kit plugin (`myProgramProgram()`) that adds them to a client with per-call overrides; `codama.resolver` plugins can supply derived account/residual inputs (sync or async) — [renderers-js README](https://raw.githubusercontent.com/codama-idl/renderers-js/main/README.md).
- `@solana-program/system` (the other common generated client) has **10,713,436** downloads/month — [downloads API](https://api.npmjs.org/downloads/point/last-month/@solana%2fprogram%2fsystem).
- Vue Solana already has `useTokenAccounts`/`useTokenBalance` and a client/payer/plan/send stack; token _mutation_ helpers (ATA creation, mint, transfer) are not listed in its composable inventory — [repository handoff notes](./../../../../AGENTS.md) (local file, read only).

### Inferences

- Generated clients make instruction construction, PDA derivation, account decoding, error identification and event parsing type-safe, and the new plugin shape means a generated client can extend the same Kit client Vue Solana injects.
- The Vue-specific layer remains useful for: reacting to changes in mint/owner/address refs, stale-while-revalidate token balance reads, ATA discovery, subscription-driven invalidation, exposing `{isRunning, status, data, error, reset}` around generated builders, and wiring the injected wallet/payer signer into builder inputs.
- A thin, opt-in Vue composable wrapper over `@solana-program/token` (or generic Codama-plugin instructions) is a better fit than bundling program clients into core; the generated clients are active and versioned independently (Kit ^8.5 token client, November 2026 releases).

### Gaps

- No evidence gathered of a maintained Vue-specific wrapper around Codama-generated clients; the opportunity is inferred from the stateless nature of generated clients, not from an existing competing product.

## 5. Are there existing Vue 3 or Nuxt Solana libraries on npm/GitHub? If so, what do they offer and how active are they?

### Takeaway

The only actively maintained, Kit-first Vue/Nuxt integration found is the project's own `@vue-solana/*` packages; the main third-party alternative, `solana-wallets-vue`, is wallet-only, web3.js v1-based, and stale since February 2025. No substantive maintained Nuxt module competitor was found.

### Cited Findings

- `@vue-solana/{core,vue,nuxt}` are at **4.4.0**, published **2026-11-19**; last-month downloads: `@vue-solana/vue` **4,809**, `@vue-solana/nuxt` **4,554**, `@vue-solana/core` **4,874** — [npm search](https://registry.npmjs.org/-/v1/search?text=vue-solana&size=20); [downloads API](https://api.npmjs.org/downloads/point/last-month/@vue-solana%2fvue).
- `solana-wallets-vue` latest **0.7.1**, published **2025-02-10** (repo `lorisleiva/solana-wallets-vue`: 195 stars, last pushed **2025-02-10**), **5,305** downloads/month; peer deps `vue ^3.2.25` and **`@solana/web3.js ^1.61.0`**; depends on wallet-adapter base + Wallet Standard packages — [npm metadata](https://registry.npmjs.org/solana-wallets-vue); [GitHub API](https://api.github.com/repos/lorisleiva/solana-wallets-vue); [downloads](https://api.npmjs.org/downloads/point/last-month/solana-wallets-vue).
- `solana-wallets-vue` features: Vue plugin with wallet options (`wallets`, `autoConnect`), global `$wallet`, `WalletMultiButton` with dark prop and default CSS, `useWallet()`, `useAnchorWallet()`, `initWallet()`, a Nuxt 3 setup section, and manual `Connection`/`Transaction`/`SystemProgram` example code — [README](https://raw.githubusercontent.com/lorisleiva/solana-wallets-vue/master/README.md).
- `@web3-wallet/vue-solana` is **0.1.3**, last updated **2022-07-26**, with only a `vue ^3.2.13` peer dependency — [npm metadata](https://registry.npmjs.org/@web3-wallet/vue-solana/latest); [npm search](https://registry.npmjs.org/-/v1/search?text=solana%20vue&size=25).
- Nuxt-oriented GitHub results are mostly stale boilerplates: `florianjs/nuxt-solana-boilerplate` (archived, last push 2022-01-08), `aidear3/nuxt-solana-boilerplate` (2 stars, 2023-04-18), `tiagoapp/nuxt3-solana` (1 star, 2022-09-14). `alexcolls/nuxt-solana` (2 stars, pushed 2026-06-01) still contains the untouched "My Module" template text ("Foo", "Bar", "Baz") — [GitHub search: solana nuxt](https://api.github.com/search/repositories?q=solana+nuxt&sort=stars&per_page=20); [alexcolls README](https://raw.githubusercontent.com/alexcolls/nuxt-solana/main/README.md).

### Inferences

- There is effectively no active third-party competitor for _full_ Vue/Nuxt Solana integration: the adjacent Vue package solves wallet connection only, on legacy web3.js v1, and has not been updated in ~21 months.
- Developer expectations for a Vue library are therefore set by React/Kit libraries and by `solana-wallets-vue`'s simple plugin + `useWallet()` ergonomics, not by a mature Vue-native Solana ecosystem.
- An opportunity exists to be the de facto Vue answer by keeping first-class Nuxt auto-imports, SSR-safe client setup, and Wallet Standard/Kit-first APIs (all already present), then filling the higher-level gaps identified below.

### Gaps

- npm/GitHub search may miss unindexed or privately maintained Vue libraries; no comprehensive survey of Chinese-language or non-npm registries was performed.
- Could not confirm whether `create-solana-dapp` templates include Vue; only the repository-level metadata was available in this pass.

## 6. Across these projects, which features consistently appear as core developer-success primitives? (ranked candidates for Vue Solana)

### Takeaway

The cross-project consensus is: one injected client + capability checks, abortable/superseded async actions, reactive live data with freshness/slot dedupe, first-class wallet/payer/identity state, high-level transfer helpers, cluster defaults, and typed program clients. Vue Solana already covers most; the highest-value _new_ candidates are token mutation helpers and simulation/debug tooling, while gill-style wrapping and React UI patterns should be rejected.

### Cited Findings

- **Client + provider + capability typing**: framework-kit `SolanaProvider`/`createClient`, `@solana/react` `ClientProvider`/`useClient`/`useClientCapability` (mount-time error with `providerHint`), Kit plugins' composable `.use()` client — [framework-kit README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/README.md); [React README](https://raw.githubusercontent.com/anza-xyz/kit/main/packages/react/README.md); [kit-plugins README](https://raw.githubusercontent.com/anza-xyz/kit-plugins/main/README.md). Kit plugins repo: 26 stars, pushed **2026-11-20** — [GitHub API](https://api.github.com/repos/anza-xyz/kit-plugins).
- **Live data trio**: `useRequest`/`useSubscription`/`useTrackedData` with stale-while-revalidate, `reconnect()`, per-attempt abort signals, slot dedupe; SWR and TanStack Query adapters — [React README](https://raw.githubusercontent.com/anza-xyz/kit/main/packages/react/README.md). Vue Solana has matching `useRequest`, `useSubscription`, `useTrackedData` and SWR adapters — [handoff notes](./../../../../AGENTS.md).
- **Tracked transaction lifecycle**: `useAction` with abort-on-supersede, `usePlanTransaction(s)`, `useSendTransaction(s)`, `useAirdrop` — [React README](https://raw.githubusercontent.com/anza-xyz/kit/main/packages/react/README.md); framework-kit `useTransactionPool`, `useWaitForSignature`, `useSendTransaction` — [react-hooks README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/packages/react-hooks/README.md).
- **Wallet primitives**: connection status/discovery, selected wallet account context, `useSignIn`, message/transaction/send signers, payer and identity hooks — [React README](https://raw.githubusercontent.com/anza-xyz/kit/main/packages/react/README.md); [react-hooks README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/packages/react-hooks/README.md); [kit-plugins README](https://raw.githubusercontent.com/anza-xyz/kit-plugins/main/README.md).
- **High-level money helpers**: `solTransfer`, `splToken` with Token-2022 auto-detection, airdrop, lookup-table/nonce reads (`@solana/client`), token create/mint/transfer builders (`gill`), generated `createMint`/`mintToATA`/`transferToATA` (`@solana-program/token`) — [@solana/client README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/packages/client/README.md); [gill README](https://raw.githubusercontent.com/gillsdk/gill/master/packages/gill/README.md); [token client index](https://raw.githubusercontent.com/solana-program/token/main/clients/js/src/index.ts).
- **Cluster defaults and one-call setup**: cluster monikers with inferred WS endpoints (`@solana/client`), `urlOrMoniker` client creation (`gill`), all-in-one RPC bundles (`solanaRpc`, `solanaDevnetRpc`, `solanaLocalRpc`) — [@solana/client README](https://raw.githubusercontent.com/solana-foundation/framework-kit/main/packages/client/README.md); [gill README](https://raw.githubusercontent.com/gillsdk/gill/master/packages/gill/README.md); [kit-plugins README](https://raw.githubusercontent.com/anza-xyz/kit-plugins/main/README.md).
- **Typed program clients and plugins**: Codama-generated typed helpers and Kit plugins, `@solana-program/token` generated from IDL — [renderers-js README](https://raw.githubusercontent.com/codama-idl/renderers-js/main/README.md); [token repo README](https://raw.githubusercontent.com/solana-program/token/main/README.md).
- **Developer ergonomics/divergence**: gill offers explorer links, rent calculation, compute-budget-aware transactions and debug mode, while `@solana/react` deliberately has **no** `useActionSWR`/`useActionQuery` (async mutation state is handled by `useAction`); both are design signals — [gill README](https://raw.githubusercontent.com/gillsdk/gill/master/packages/gill/README.md); [React README](https://raw.githubusercontent.com/anza-xyz/kit/main/packages/react/README.md).

### Inferences

- The "core developer-success primitive" pattern is consistent across every maintained project: **build once, inject everywhere; make async state observable and cancellable; make freshness explicit; give one-call helpers for the 80% flows; keep generated program clients typed and composable**.
- Vue Solana's existing architecture already matches the current official direction better than the older framework-kit/gill stacks; roadmap energy is better spent on _domain helpers_ (token mutations, simulation/debug, receipts) than on another abstraction over Kit.
- Because the Vue ecosystem lacks an active alternative, "mature library" expectations will be imported from React docs; documenting Vue equivalents of familiar primitives (provider, actions, live data, capability errors, signers) in examples is itself a high-value feature.

### Gaps

- No direct user interviews, issue-thread analysis, or tutorial sentiment data were collected (web search was unavailable), so "developer expectations" are inferred from documented API surfaces and adoption metrics, not stated user preference.
- Download counts are last-month snapshots and can include CI/transitive installs; they indicate relative visibility only.
