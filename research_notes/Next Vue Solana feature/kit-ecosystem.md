# Official Solana/Kit ecosystem capabilities as next-feature inputs (2026-11-21)

## 1. What official Kit and its ecosystem now provide, and what is framework wiring

### Takeaway

By late 2026 Kit is no longer just low-level RPC/transaction primitives: official packages cover typed account fetching/decoding, reactive stores, robust subscriptions, transaction planning/signing/sending, wallet state/SIWS, signer/payer plugins, Codama-generated program clients, and Mobile Wallet Adapter bridges. Most remaining Vue value is lifecycle/state/policy wiring (reactivity, SSR, persistence, error UX, user choices), not reimplementing protocol mechanics.

### Cited Findings

- `@solana/kit` latest was `8.6.0` on 2026-11-21; the latest stable GitHub release was `v8.6.0` published 2026-10-28, with v8.x minors on 2026-08-21 (`v8.0.0`), 2026-08-27, 2026-08-29, 2026-09-09, 2026-09-28, and 2026-10-13. A `8.7.0-canary-20261120143344` build existed on 2026-11-20, so 8.7 was actively developing but not stable — [npm registry](https://registry.npmjs.org/@solana/kit), [release list](https://github.com/anza-xyz/kit/releases), [v8.6.0 release](https://github.com/anza-xyz/kit/releases/tag/v8.6.0).
- Kit describes itself as a tree-shakable JavaScript SDK for Node, web, and React Native; the root package re-exports granular modules, and Kit has no third-party dependencies and no classes except `SolanaError`. The README explicitly discusses dual-package hazard as a motivation for its functional design — [Kit README](https://github.com/anza-xyz/kit/blob/main/README.md).
- Protocol/RPC layer includes typed RPC calls, custom transports (round robin, sharding, retry, failover), request aborting, cluster-constrained/augmented APIs, and user-defined RPC methods — [Kit README: RPC](https://github.com/anza-xyz/kit/blob/main/README.md#rpc).
- Subscriptions are exposed as async iterators with surfaced transport errors, gap recovery, abort handling, custom WebSocket transports, cluster constraints, and explicit inclusion of unstable subscriptions — [Kit README: RPC Subscriptions](https://github.com/anza-xyz/kit/blob/main/README.md#rpc-subscriptions).
- Account primitives live in `packages/accounts/src` as `fetchAccount`, `fetchJsonParsedAccounts`, `decodeAccount`, `parseAccount`, and `maybeAccount`, with assertions such as `assertAccountsExist` and `assertAccountsDecoded` used by Kit’s own helpers — [Kit accounts source](https://github.com/anza-xyz/kit/tree/main/packages/accounts/src), [fetch-lookup-tables.ts](https://github.com/anza-xyz/kit/blob/main/packages/kit/src/fetch-lookup-tables.ts).
- RPC API source includes typed methods for `getAccountInfo`, `getMultipleAccounts`, `getProgramAccounts`, `getTokenAccountBalance`, `getTokenAccountsByOwner`, and `getTokenAccountsByDelegate`; parsed token/nonce/address-lookup-table account types also ship in Kit — [Kit RPC API source](https://github.com/anza-xyz/kit/tree/main/packages/rpc-api/src), [Kit parsed types](https://github.com/anza-xyz/kit/tree/main/packages/rpc-parsed-types/src).
- Kit v7.1.0 (2026-08-14) added a `ClientWithFetchAccounts` interface and helpers to create client interfaces from a raw `Rpc`; v6.10.0 (2026-06-16) added framework-neutral reactive sources/stores compatible with `useSyncExternalStore`, Svelte, and similar bindings — [v7.1.0 release](https://github.com/anza-xyz/kit/releases/tag/v7.1.0), [v6.10.0 release](https://github.com/anza-xyz/kit/releases/tag/v6.10.0).
- Transaction support includes typed transaction messages, signers, compute-budget helpers, durable-nonce lifetime helpers, size/version validation, transaction confirmation strategies, and helpers such as `fetchAddressesForLookupTables` and `sendAndConfirmDurableNonceTransactionFactory` — [Kit transaction source tree](https://github.com/anza-xyz/kit/tree/main/packages/transaction-messages/src), [fetch-lookup-tables.ts](https://github.com/anza-xyz/kit/blob/main/packages/kit/src/fetch-lookup-tables.ts), [send-and-confirm-durable-nonce-transaction.ts](https://github.com/anza-xyz/kit/blob/main/packages/kit/src/send-and-confirm-durable-nonce-transaction.ts).
- Priority-fee primitives are mature: `setTransactionMessageComputeUnitPrice` / `getTransactionMessageComputeUnitPrice` operate on legacy and v0 messages, while v1 uses a resource header with `priorityFeeLamports`; resource-limit estimation for CU and loaded-account data size was added in v6.10.0 and filled out for v1 in later releases — [compute-unit-price.ts](https://github.com/anza-xyz/kit/blob/main/packages/transaction-messages/src/compute-unit-price.ts), [v6.10.0 release](https://github.com/anza-xyz/kit/releases/tag/v6.10.0), [v8.3.0 release](https://github.com/anza-xyz/kit/releases/tag/v8.3.0).
- Official `@solana/kit-plugins` provides five published packages as of 2026-11-21: RPC, signer, instruction-plan, LiteSVM, and wallet. Bundle plugins configure full clients, while granular plugins compose `rpc`, `rpcSubscriptions`, `getMinimumBalance`, `airdrop`, `planTransaction(s)`, `signTransaction(s)`, and `sendTransaction(s)` — [plugin repository README](https://github.com/anza-xyz/kit-plugins#readme), [plugin packages](https://github.com/anza-xyz/kit-plugins/tree/main/packages).
- `solanaRpc` installs RPC, subscriptions, minimum-balance computation, planning, signing, and execution; config covers transaction version, priority fee, resource-limit estimation, max instructions per transaction, `maxConcurrency`, and `skipPreflight`. Cluster-specific wrappers enforce mainnet vs. devnet/testnet/local airdrop capability at the type level — [kit-plugin-rpc README](https://github.com/anza-xyz/kit-plugins/blob/main/packages/kit-plugin-rpc/README.md).
- Official wallet plugin (`@solana/kit-plugin-wallet@0.23.0`) performs Wallet Standard discovery, connection lifecycle, account selection, reconnect state, payer/identity signer mapping, `signMessage`, `signOffchainMessage`, and SIWS-as-connect with response verification. It also exposes React hooks under `/react`; no Vue binding is provided — [kit-plugin-wallet README](https://github.com/anza-xyz/kit-plugins/blob/main/packages/kit-plugin-wallet/README.md), [npm metadata](https://registry.npmjs.org/@solana/kit-plugin-wallet/latest).
- Kit v7.1.0 (2026-08-14) added official React hooks `usePayer`, `useIdentity`, `usePlanTransaction(s)`, `useSendTransaction(s)`, and `useAirdrop`, confirming that framework adapters are an area the Kit maintainers themselves consider useful — [v7.1.0 release](https://github.com/anza-xyz/kit/releases/tag/v7.1.0).
- Codama generates Kit-compatible program clients with typed accounts, instructions, PDAs, defined types, errors, events, codecs, and program plugins; `@codama/renderers-js` v3 targets Codama IDL v2 — [Codama README](https://github.com/codama-idl/codama#readme), [renderers-js README](https://github.com/codama-idl/renderers-js#readme).
- Mobile Wallet Adapter includes an official JavaScript Kit convenience wrapper, `@solana-mobile/mobile-wallet-adapter-protocol-kit@3.0.2`, whose peer is `@solana/kit@^8.0.0` and whose dependencies include Kit 8.6 transaction/message packages — [MWA README](https://github.com/solana-mobile/mobile-wallet-adapter#readme), [npm metadata](https://registry.npmjs.org/@solana-mobile/mobile-wallet-adapter-protocol-kit/latest).

### Inferences

- Separate protocol capabilities from framework work: protocol/RPC = account codecs, typed RPC/subscriptions, transaction planning, priority fees, nonces, ALT fetching, wallet signing, SIWS verification, generated program clients. Framework work = turning these into reactive state machines, handling component mount/unmount, SSR guards, persisted account selection, stale-while-revalidate, user-facing fee/speed policy, and consistent errors.
- A Vue composable that only calls `fetchAccount`, `setTransactionMessageComputeUnitPrice`, `fetchAddressesForLookupTables`, or `client.sendTransaction()` is likely thin. A composable that owns subscription lifecycle, capability checks, concurrency, cancellation, stale data, persistence, and UI error semantics is not.
- The official React hooks are a useful product signal but not a reason for Vue Solana to mirror the React API literally; Vue’s reactive refs/computed/watch lifecycle is the differentiator.
- Program clients are best consumed as generated, app/program-specific packages. A generic library should provide reactive adapters over their codecs and plugin namespaces, not generate or hand-maintain program clients.

### Gaps

- `solana.com/docs` pages returned HTTP 429 during this research, so no claims above rely on that site; primary GitHub/npm sources were used instead — [Solana docs](https://solana.com/docs).
- No reliable public publish timestamps were available from npm’s `/latest` metadata for plugin packages; dates above come from GitHub releases where present, and exact package versions from npm.
- I found no official single-call “wallet token portfolio” helper in Kit or the inspected `@solana-program/*` client trees; this is a negative finding from inspected sources, not proof that a third-party provider SDK lacks one.

## 2. Which dapp workflows still need boilerplate, and which Kit coverage makes Vue wrappers redundant

### Takeaway

The highest-boilerplate areas are token/token-2022 portfolio reads, transaction reliability policy, reactive subscriptions/account state, wallet UI state across discovery/reconnect/selection, and relayer-oriented nonce/ALT lifecycle management. Raw fetch/decode, transport retries, wallet signature verification, SIWS response checks, basic plan/send, and priority-fee setters are already well served by Kit/plugins and should not be duplicated.

### Cited Findings

- **Account fetch/decoding:** Kit has first-class fetch/decode/parse/maybe modules and client-level fetch capability; calling them from Vue only needs a thin reactive adapter unless adding SWR, subscriptions, or typed program-account decoding — [accounts source](https://github.com/anza-xyz/kit/tree/main/packages/accounts/src), [v7.1.0 release](https://github.com/anza-xyz/kit/releases/tag/v7.1.0).
- **Token accounts/balances:** Official RPC supports owner/delegate token-account queries and balance reads, and parsed token account types ship in Kit, but composing ATA derivation, mint account reads, decimals/UI amounts, multiple owner accounts, refresh, and token-2022 metadata remains application work — [getTokenAccountsByOwner.ts](https://github.com/anza-xyz/kit/blob/main/packages/rpc-api/src/getTokenAccountsByOwner.ts), [getTokenAccountBalance.ts](https://github.com/anza-xyz/kit/blob/main/packages/rpc-api/src/getTokenAccountBalance.ts), [token-accounts.ts](https://github.com/anza-xyz/kit/blob/main/packages/rpc-parsed-types/src/token-accounts.ts).
- **Token-2022:** `@solana-program/token-2022@0.20.1` was released 2026-11-04 and includes generated mint/token/multisig account codecs, many instruction builders (including confidential transfer/fee extensions), PDAs, and extension types; its peer/dependency graph includes `@solana/kit@^8.5.0`, `@solana/sysvars@^8.0.0`, `@solana/zk-sdk@^0.5.4`, record, system, and zk-elgamal-proof packages — [release](https://github.com/solana-program/token-2022/releases/tag/js%40v0.20.1), [npm metadata](https://registry.npmjs.org/@solana-program/token-2022/latest), [generated client tree](https://github.com/solana-program/token-2022/tree/main/clients/js/src/generated).
- **Transaction planning/sending/confirmation:** `solanaRpc` already installs planning, signing, sending, and confirmation-oriented execution, with lazy payer reads, resource estimation, priority-fee configuration, concurrency limits, and `skipPreflight`; a Vue wrapper mainly adds action state, capability errors, and wallet/relayer composition — [kit-plugin-rpc README](https://github.com/anza-xyz/kit-plugins/blob/main/packages/kit-plugin-rpc/README.md).
- **Reliability:** Kit README documents composable retry, failover, round-robin, and sharding transports, while subscription APIs surface failures and gap events instead of silently retrying. The policy decision (“which strategy for this app/user?”) remains outside Kit — [Kit README](https://github.com/anza-xyz/kit/blob/main/README.md), [Kit README: Subscriptions](https://github.com/anza-xyz/kit/blob/main/README.md#rpc-subscriptions).
- **Priority fees:** Message helpers, v1 resource-header fees, simulation-based resource estimation, and planner-level `priorityFeeLamports` / `microLamportsPerComputeUnit` exist. What remains is UX/policy: presets, max spend, simulation failure handling, and confirmation reporting — [compute-unit-price.ts](https://github.com/anza-xyz/kit/blob/main/packages/transaction-messages/src/compute-unit-price.ts), [kit-plugin-rpc README](https://github.com/anza-xyz/kit-plugins/blob/main/packages/kit-plugin-rpc/README.md).
- **Durable nonces:** Kit has nonce lifetime types/guards, `setTransactionMessageLifetimeUsingDurableNonce` (source file), confirmation strategies for nonce invalidation, and a `sendAndConfirmDurableNonceTransactionFactory` that handles the race where nonce changes before signature confirmation. Application wiring still includes nonce account creation/advance authority, nonce fetching, pool/rotation policy, and UI state — [durable-nonce.ts](https://github.com/anza-xyz/kit/blob/main/packages/transaction-messages/src/durable-nonce.ts), [confirmation-strategy-nonce.ts](https://github.com/anza-xyz/kit/blob/main/packages/transaction-confirmation/src/confirmation-strategy-nonce.ts), [send-and-confirm-durable-nonce-transaction.ts](https://github.com/anza-xyz/kit/blob/main/packages/kit/src/send-and-confirm-durable-nonce-transaction.ts).
- **Address lookup tables:** Kit supplies `fetchAddressesForLookupTables`, message decompilation that fetches lookup tables, and generated system-program instruction builders/PDA helpers for creating lookup tables. A Vue wrapper is most useful for caching decoded table contents and exposing per-transaction table selection, not for low-level fetch/compile logic — [fetch-lookup-tables.ts](https://github.com/anza-xyz/kit/blob/main/packages/kit/src/fetch-lookup-tables.ts), [decompile-transaction-message-fetching-lookup-tables.ts](https://github.com/anza-xyz/kit/blob/main/packages/kit/src/decompile-transaction-message-fetching-lookup-tables.ts), [Kit README: Program Clients](https://github.com/anza-xyz/kit/blob/main/README.md#program-clients).
- **RPC subscriptions:** Kit’s subscription subsystem handles async iterators, aborting, gap recovery, and custom transports. Vue/Nuxt still needs reactive starts/stops, component cleanup, SSR/browser gating, stale-data retention, and dedupe with initial RPC reads — [Kit README: RPC Subscriptions](https://github.com/anza-xyz/kit/blob/main/README.md#rpc-subscriptions), [v7.0.0 release](https://github.com/anza-xyz/kit/releases/tag/v7.0.0).
- **Wallet Standard / SIWS:** The official wallet plugin now covers discovery, connect/disconnect, account switching, reconnecting state, signer mapping, `signMessage`, offchain message signing, SIWS, and verification of returned outputs. Remaining UI concerns include selected-account persistence, multi-wallet policy (for example, exclusive connect), reconnect banners, transaction-version capability checks, and Vue reactivity — [kit-plugin-wallet README](https://github.com/anza-xyz/kit-plugins/blob/main/packages/kit-plugin-wallet/README.md).
- **Mobile wallets:** MWA has official protocol and Kit-wrapper packages plus a Wallet Standard mobile package; the README points to a specification, JS reference implementation, Kit convenience wrapper, and example apps. The remaining framework work is lazy loading, deep-link/callback routing, session state, platform gating, and UI affordances — [MWA README](https://github.com/solana-mobile/mobile-wallet-adapter#readme), [MWA releases](https://github.com/solana-mobile/mobile-wallet-adapter/releases).
- **Program clients / Codama:** Generated clients already provide typed account/instruction/PDA/event/error helpers and Kit plugins, so manually wrapping instruction construction in a generic Vue library would be redundant. The useful Vue surface is generic reactive account/subscription/event adapters around generated codecs and client namespaces — [renderers-js README](https://github.com/codama-idl/renderers-js#readme), [Kit README: Program Clients](https://github.com/anza-xyz/kit/blob/main/README.md#program-clients).

### Inferences

- Thin/redundant: raw account fetch/decode; address codecs; basic transaction message assembly; raw priority-fee setters; raw subscription transport; ALT fetch; raw wallet discovery/connect; wallet signature/SIWS verification; generated instruction builders.
- Valuable: token-portfolio aggregation; SWR/subscription state machines; fee/reliability policy; durable-nonce pool state; ALT cache; wallet UI state and persistence; deferred MWA integration; program-client-aware reactive helpers.
- A good rule: if a composable’s body is essentially one Kit call plus `ref`, it is thin; if it coordinates multiple calls, lifecycles, cancellations, and policies, it is a real feature.

### Gaps

- No official Kit helper was found that aggregates all SPL Token and Token-2022 accounts for an owner with mint metadata/decimals; confirm against provider SDKs before claiming uniqueness beyond the official ecosystem.
- No official Vue binding exists in Kit; the React hooks show the intended shape but cannot be copied directly.
- The MWA browser/deep-link UX is partly platform/documentation driven; source inspection alone does not establish which flows are reliable across current Android/iOS browsers.

## 3. Stability, security/dependency risks, and ranked next Vue Solana features

### Takeaway

Core Kit 8.x is stable enough to depend on, but official plugin packages are still 0.x, several high-level APIs changed in 7.x/8.x, and newer RPC/program-client surfaces are explicitly experimental or chain-specific. The biggest dependency risk is duplicate Kit copies from granular `@solana/*` packages or wrappers with their own Kit ranges; the biggest security improvement in 2026 is wallet-signature/SIWS verification becoming part of official Kit/plugin code.

### Cited Findings

- Stability signals: Kit stable is 8.6.0, plugin RPC/signer/wallet are 0.23.0 with peer `@solana/kit@^8.6.0`, `@solana-program/system@0.16.0` and `@solana-program/token-2022@0.20.1` peer `@solana/kit@^8.5.0`, Wallet Standard features are `1.5.0`, and MWA protocol Kit wrapper is `3.0.2` — [Kit npm](https://registry.npmjs.org/@solana/kit), [plugin RPC npm](https://registry.npmjs.org/@solana/kit-plugin-rpc/latest), [plugin signer npm](https://registry.npmjs.org/@solana/kit-plugin-signer/latest), [plugin wallet npm](https://registry.npmjs.org/@solana/kit-plugin-wallet/latest), [system npm](https://registry.npmjs.org/@solana-program/system/latest), [token-2022 npm](https://registry.npmjs.org/@solana-program/token-2022/latest), [wallet-standard-features npm](https://registry.npmjs.org/@solana/wallet-standard-features/latest), [MWA Kit npm](https://registry.npmjs.org/@solana-mobile/mobile-wallet-adapter-protocol-kit/latest).
- Churn signals: v8.0.0 (2026-08-21) removed deprecated compute-unit estimation helpers and fixed-size transaction constants and filled SIMD-0385 v1 transaction gaps; v8.2.0 (2026-08-29) made a breaking change to the concurrent transaction-plan executor introduced only in 8.1.0; v8.6.0 (2026-10-28) was still changing v1 transaction decoding and transaction size constants — [v8.0.0 release](https://github.com/anza-xyz/kit/releases/tag/v8.0.0), [v8.2.0 release](https://github.com/anza-xyz/kit/releases/tag/v8.2.0), [v8.6.0 release](https://github.com/anza-xyz/kit/releases/tag/v8.6.0).
- Reactive store APIs also churned: v7.0.0 (2026-06-30) dropped auto-connect from `ReactiveStreamStore`, replaced construction-time abort signals with `withSignal()`, and changed RPC/subscription reactive sources; v7.1.0 added `bridgeStoreToAsyncIterable` — [v7.0.0 release](https://github.com/anza-xyz/kit/releases/tag/v7.0.0), [v7.1.0 release](https://github.com/anza-xyz/kit/releases/tag/v7.1.0).
- Chain-specific/experimental surfaces: `getAgGenesisCert` was added in v8.3.0 for nodes with an Alpenglow genesis certificate; `getTransactionsForAddress` was added in v7.1.0 as part of the upcoming `solana-rpc` spec/superbank project and was already offered by major providers; Kit’s GraphQL package is introduced as something maintainers are “working on”; Codama renderers-js v3 targets Codama v2 while v2 was still described as release-candidate — [v8.3.0 release](https://github.com/anza-xyz/kit/releases/tag/v8.3.0), [v7.1.0 release](https://github.com/anza-xyz/kit/releases/tag/v7.1.0), [Kit README: GraphQL](https://github.com/anza-xyz/kit/blob/main/README.md#graphql), [renderers-js README](https://github.com/codama-idl/renderers-js#readme).
- Security hardening in v8.5.0 (2026-10-13): `verifySignature()` became strict against small-order public keys/`R` points, and `createMessageSignerFromWalletAccount` began verifying wallet-returned signatures and output counts; v8.6.0 added a specific error for unsupported wallet feature versions, such as `solana:signIn` options introduced in feature v1.1.0 — [v8.5.0 release](https://github.com/anza-xyz/kit/releases/tag/v8.5.0), [v8.6.0 release](https://github.com/anza-xyz/kit/releases/tag/v8.6.0).
- The wallet plugin verifies SIWS/offchain outputs but explicitly does not verify that the SIWS text inside an offchain message matches the caller’s input; that remains app/server work — [kit-plugin-wallet README](https://github.com/anza-xyz/kit-plugins/blob/main/packages/kit-plugin-wallet/README.md).
- Duplicate-copy risk is concrete: the root Kit package re-exports granular modules, the MWA Kit wrapper depends directly on `@solana/transactions@^8.6.0` and `@solana/transaction-messages@^8.6.0`, token-2022 peers on `@solana/sysvars@^8.0.0`, and the wallet plugin depends on `@solana/wallet-account-signer@^8.6.0`. Different resolutions can create multiple `SolanaError`/signer/subscription identities; Kit’s own README calls out dual-package hazard — [Kit README](https://github.com/anza-xyz/kit/blob/main/README.md), [MWA Kit npm](https://registry.npmjs.org/@solana-mobile/mobile-wallet-adapter-protocol-kit/latest), [token-2022 npm](https://registry.npmjs.org/@solana-program/token-2022/latest), [wallet plugin npm](https://registry.npmjs.org/@solana/kit-plugin-wallet/latest).
- Heavyweight dependencies are concentrated in optional areas: `@solana-mobile/wallet-standard-mobile@0.7.1` depends on `lit`, `qrcode`, Wallet Standard packages, and MWA protocol; token-2022 includes zk-specific dependencies; `@solana/kit-plugin-wallet` has React/UI-registry peers/dependencies — [wallet-standard-mobile npm](https://registry.npmjs.org/@solana-mobile/wallet-standard-mobile/latest), [token-2022 npm](https://registry.npmjs.org/@solana-program/token-2022/latest), [wallet plugin npm](https://registry.npmjs.org/@solana/kit-plugin-wallet/latest).

### Inferences

- Dependency policy: depend on `@solana/kit` as the single source of truth, re-export its surface rather than adding granular `@solana/*` packages directly, keep workspace overrides/peer ranges aligned, and lazy-load optional MWA/token-2022/QR paths. Do not wrap a second SDK that carries its own Kit range.
- Stability policy: build on Kit 8.x core primitives; treat plugin 0.x names, v1 transaction messages, instruction-plan executor internals, reactive store APIs, GraphQL, Alpenglow RPC methods, and Codama v2/v3 renderer details as version-sensitive and isolate them behind thin adapters.
- Security policy: use official verification helpers, verify SIWS text/claims server-side, never treat client-side wallet verification as authorization, and preserve capability checks so a missing payer/signer fails before network I/O.

**Ranked next Vue Solana features**

1. **Official-plugin-backed reactive wallet + SIWS/offchain state adapter.** Why: discovery, connect/reconnect, account switching, signer mapping, SIWS, and output verification are now officially implemented, but only React hooks ship; Vue still needs reactive state, persistence, capability checks, SSR-safe discovery, and a clear app-wide selected-account policy — [kit-plugin-wallet README](https://github.com/anza-xyz/kit-plugins/blob/main/packages/kit-plugin-wallet/README.md), [v7.1.0 release](https://github.com/anza-xyz/kit/releases/tag/v7.1.0).
2. **Token / Token-2022 portfolio primitive.** Why: RPC and generated clients supply the low-level pieces, but aggregating owned accounts, ATAs, mints, decimals/UI amounts, metadata/extensions, and refresh/subscription state is still substantial app boilerplate. Keep Token-2022 heavy code lazy and optional — [RPC token methods](https://github.com/anza-xyz/kit/tree/main/packages/rpc-api/src), [token-2022 client tree](https://github.com/solana-program/token-2022/tree/main/clients/js/src/generated), [token-2022 npm](https://registry.npmjs.org/@solana-program/token-2022/latest).
3. **Transaction reliability/fee policy composable layered over plugin RPC.** Why: plan/sign/send, resource estimation, priority fees, concurrency, skip-preflight, retry/failover transports, and confirmation exist; apps still need presets, spend caps, failure classification, and reactive progress. This is high-value without reimplementing Kit mechanics — [kit-plugin-rpc README](https://github.com/anza-xyz/kit-plugins/blob/main/packages/kit-plugin-rpc/README.md), [Kit README](https://github.com/anza-xyz/kit/blob/main/README.md).
4. **Program-client-aware reactive account/event adapter.** Why: Codama now generates strong typed clients and Kit plugins, so the useful Vue addition is lifecycle/state around generated codecs and event identifiers, not another program client generator — [renderers-js README](https://github.com/codama-idl/renderers-js#readme), [Kit README: Program Clients](https://github.com/anza-xyz/kit/blob/main/README.md#program-clients).
5. **Durable-nonce + ALT lifecycle helpers for relayers/high-throughput apps.** Why: official primitives are solid but stateful application policy (nonce pools, invalidation handling, ALT caching/selection) remains; narrower audience than wallet/token/fee work, so rank lower — [durable nonce source](https://github.com/anza-xyz/kit/blob/main/packages/transaction-messages/src/durable-nonce.ts), [durable nonce send/confirm](https://github.com/anza-xyz/kit/blob/main/packages/kit/src/send-and-confirm-durable-nonce-transaction.ts), [fetch-lookup-tables.ts](https://github.com/anza-xyz/kit/blob/main/packages/kit/src/fetch-lookup-tables.ts).

### Gaps

- I did not verify whether a given Vue Solana release already implements each candidate feature; this research maps official capabilities, not the repository’s current diff.
- No public roadmap with dated future Kit releases was found in the inspected primary sources; “release direction” is inferred from released changelogs and repository state.
- Reliable current Solana.com documentation text could not be retrieved because of rate limiting; consult the official docs again when accessible for product-level guidance — [Solana docs](https://solana.com/docs).
