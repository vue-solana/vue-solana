# Solana UI / wallet-connect ecosystem and Vue/Nuxt UI conventions (2026-11-25)

Scope: external ecosystem review for the product question “should vue-solana ship a UI library?”. Primary sources are npm registry/download APIs, GitHub APIs/source, and official docs. Download figures are **verified observed package downloads**, not unique users, and may include CI/transitive installs; weekly window is 2026-11-17..2026-11-23 unless another range is stated. “Verified” means the source directly shows the fact; “Inferred” means a product conclusion drawn from those facts.

## 1. What Solana Wallet Adapter UI packages actually provide, and what are their maintenance/dependency costs?

### Takeaway

The official Wallet Adapter UI surface is now effectively one maintained React/CSS package, `@solana/wallet-adapter-react-ui` (0.9.40, **229,456 weekly downloads**). It supplies a connect button, modal, wallet list, copy-address/change-wallet/disconnect dropdown, icons, focus trap and Escape handling, but **no transaction toasts, no transaction UI, no real theming system, and no Vue components**. Material UI and Ant Design variants are deprecated and near-zero usage. Mobile deep links are delegated to wallet adapters/MWA and are a recurring complaint area.

### Cited Findings

- **Verified — maintained UI package and adoption**: `@solana/wallet-adapter-react-ui@0.9.40` was published 2026-09-10 and had **229,456 weekly downloads** (2026-11-17..23) and 949,730 monthly downloads; it depends on `@solana/wallet-adapter-base`, `@solana/wallet-adapter-base-ui`, and `@solana/wallet-adapter-react`, with peer deps `@solana/web3.js ^1.99.0`, `react`, `react-dom` — [npm registry](https://registry.npmjs.org/@solana%2Fwallet-adapter-react-ui), [npm weekly downloads](https://api.npmjs.org/downloads/point/last-week/@solana%2Fwallet-adapter-react-ui), [npm monthly downloads](https://api.npmjs.org/downloads/point/last-month/@solana%2Fwallet-adapter-react-ui).
- **Verified — official package layout**: the repository’s `PACKAGES.md` lists only `react-ui` under “UI Components”, described as “Components for React (no UI framework, just CSS)”, and lists Vue as a **community-maintained** integration — [PACKAGES.md](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/PACKAGES.md).
- **Verified — exports show no transaction UI**: `react-ui/src/index.ts` exports only modal/button/icon primitives (`useWalletModal`, base buttons, `WalletModal`, `WalletModalProvider`, `WalletIcon`, `WalletMultiButton`, connect/disconnect buttons); there are no toast, notification, transaction-status, account-switcher, or balance components — [react-ui index.ts](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/index.ts).
- **Verified — connect modal behavior**: `WalletModalProvider` mounts `WalletModal` when `visible`; `WalletModal` portals into `body`, splits wallets into installed/not-installed, collapses not-installed wallets, closes on overlay/close click and Escape, locks `document.body.style.overflow`, and traps Tab focus among `button` elements — [WalletModalProvider.tsx](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/WalletModalProvider.tsx), [WalletModal.tsx](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/WalletModal.tsx).
- **Verified — a11y is partial but present**: the modal has `role="dialog"`, `aria-modal="true"`, and `aria-labelledby="wallet-adapter-modal-title"`; buttons set `type="button"`, `tabIndex`, and `disabled`; the focus trap queries only `button` elements, so non-button interactive content would not be included — [WalletModal.tsx lines 120–128](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/WalletModal.tsx), [Button.tsx](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/Button.tsx).
- **Verified — wallet list and labels**: `WalletListItem` renders an icon, adapter name, and “Detected” badge; `WalletMultiButton` hardcodes English labels such as “Change wallet”, “Connecting ...”, “Copy address”, “Copied”, “Disconnect”, “Connect”, and “Select Wallet”; `WalletConnectButton` and `WalletDisconnectButton` likewise hardcode English strings — [WalletListItem.tsx](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/WalletListItem.tsx), [WalletMultiButton.tsx](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/WalletMultiButton.tsx), [WalletConnectButton.tsx](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/WalletConnectButton.tsx).
- **Verified — account menu is minimal**: `BaseWalletMultiButton` opens a dropdown with only copy address, change wallet, and disconnect; it uses `role="menu"`/`role="menuitem"` and `aria-expanded`, but account-switching between multiple authorized accounts is not part of this UI — [BaseWalletMultiButton.tsx](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/BaseWalletMultiButton.tsx).
- **Verified — theming is CSS overriding, not a theme API**: `styles.css` imports Google Fonts (`DM Sans`) and hardcodes colors such as `#512da8` and `#2c2d30`; customization is done by overriding `.wallet-adapter-*` classes — [styles.css](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/styles.css). Issue #397 is a long-running “Overriding WalletMultiButton style from react-ui” thread with workarounds using `!important`, `all: unset`, and Tailwind `@apply` — [issue #397](https://github.com/anza-xyz/wallet-adapter/issues/397).
- **Verified — Material/Ant Design UI packages are deprecated**: `@solana/wallet-adapter-material-ui@0.16.35` and `@solana/wallet-adapter-ant-design@0.11.33` were last published 2025-03-17 and are explicitly marked “This package is no longer supported”; weekly downloads were **290** and **122** respectively (2026-11-17..23) — [Material npm](https://registry.npmjs.org/@solana%2Fwallet-adapter-material-ui), [Ant npm](https://registry.npmjs.org/@solana%2Fwallet-adapter-ant-design), [Material downloads](https://api.npmjs.org/downloads/point/last-week/@solana%2Fwallet-adapter-material-ui), [Ant downloads](https://api.npmjs.org/downloads/point/last-week/@solana%2Fwallet-adapter-ant-design). Their last versions peer-depend on `@mui/material`/`@mui/icons-material` or `antd`/`@ant-design/icons`, plus React and `@solana/web3.js` — [Material latest](https://registry.npmjs.org/@solana%2Fwallet-adapter-material-ui/latest), [Ant latest](https://registry.npmjs.org/@solana%2Fwallet-adapter-ant-design/latest).
- **Verified — maintenance signal**: `anza-xyz/wallet-adapter` had 2,030 stars, 43 open issues, and was last pushed 2026-10-06; it is not archived — [GitHub API](https://api.github.com/repos/anza-xyz/wallet-adapter).
- **Verified — mobile handoff is not a UI-component feature**: the UI selects a wallet name; deep-link behavior lives in adapters/MWA. Issue #385 “Support Phantom universal links/deeplinks” was closed with the maintainer statement that it “doesn’t make sense in Wallet Adapter” and that MWA covers the use case — [issue #385](https://github.com/anza-xyz/wallet-adapter/issues/385). iOS Safari deep-link failure was reported in #988, where the reporter suspected authorization/deep-link URL handling — [issue #988](https://github.com/anza-xyz/wallet-adapter/issues/988). An Android Web “Mobile Wallet Adapter option in wallet selection modal does nothing” report exists as #799 — [issue #799](https://github.com/anza-xyz/wallet-adapter/issues/799).

### Inferences

- Wallet Adapter UI’s durable surface is **wallet connection UX**, not general dapp UX. A Vue Solana UI package would not be “catching up” by copying transaction toasts or account menus; those are absent from the official React UI as well.
- The main gaps a Vue-native package could improve are: real theme/token integration with Vue UI ecosystems, locale/i18n-friendly labels, multi-account selection, explicit SSR gates, and better uninstalled-wallet/deep-link recovery states. These are inferred from the source and issue threads, not from user interviews.
- Importing Wallet Adapter UI would impose a heavy legacy cost: React + React DOM + `@solana/web3.js` v1 peer plus a separate wallet adapter model. That is a poor fit for a Kit-first Vue package.
- The high download count (229k/week for React UI) reflects the React/web3.js v1 install base; it is not evidence that Vue users want the same API.

### Gaps

- No direct user survey was found explaining why developers choose or reject `wallet-adapter-react-ui`; evidence is API/source inspection and issue reports.
- No reliable bundle-size measurement of the current `@solana/wallet-adapter-react-ui` package was gathered; the only citable size report is old (2022) and concerns the broader wallet-adapter/wallets aggregate.
- The Material/Ant Design source trees are no longer in the current repo tree; the feature comparison relies on npm metadata and deprecation notices.

## 2. What is the current status of Kit’s official wallet plugin/wallet-standard stack, does it offer UI, and would it conflict with vue-solana’s custom MWA/iOS layer?

### Takeaway

Kit’s official `@solana/kit-plugin-wallet@0.23.0` is active and headless: wallet discovery, connection lifecycle, account selection, signer/payer/identity mapping, reconnect, SIWS, verification, plus **React hooks only**. It ships **no modal, no component library, and no Vue binding**; its own README shows how to bind state manually with a Vue `shallowRef`. Adopting it wholesale would conflict with vue-solana’s existing discovery/registry, MWA session, and iOS deep-link adapters unless it replaces that layer rather than being added alongside it.

### Cited Findings

- **Verified — package status/adoption**: `@solana/kit-plugin-wallet@0.23.0` was published 2026-10-30 and had **7,044 weekly downloads** (2026-11-17..23) and 26,848 monthly downloads — [npm registry](https://registry.npmjs.org/@solana%2Fkit-plugin-wallet), [weekly downloads](https://api.npmjs.org/downloads/point/last-week/@solana%2Fkit-plugin-wallet), [monthly downloads](https://api.npmjs.org/downloads/point/last-month/@solana%2Fkit-plugin-wallet).
- **Verified — maintenance signal**: `anza-xyz/kit-plugins` had 26 stars, 9 open issues, and was pushed 2026-11-25; it is not archived — [GitHub API](https://api.github.com/repos/anza-xyz/kit-plugins). Core `anza-xyz/kit` had 703 stars and was pushed 2026-11-25 — [GitHub API](https://api.github.com/repos/anza-xyz/kit).
- **Verified — plugin surface**: four plugins (`walletSigner`, `walletPayer`, `walletIdentity`, `walletWithoutSigner`) add a `client.wallet` namespace and optionally expose the connected wallet signer as `client.payer`/`client.identity`; state includes `wallets`, `connected`, `status`, and `reconnectingTo`; actions include `connect`, `disconnect`, `selectAccount`, `signMessage`, `signOffchainMessage`, and `signIn` — [kit-plugin-wallet README](https://raw.githubusercontent.com/anza-xyz/kit-plugins/main/packages/kit-plugin-wallet/README.md).
- **Verified — no UI components**: the README’s only framework-specific section is “React hooks”, listing `useWalletStatus`, `useConnectedWallet`, `useReconnectingAccount`, `useWallets`, `useIsWalletReady`, `WalletReadyGate`, and action hooks (`useConnect`, `useDisconnect`, `useSignIn`, `useSignMessage`, `useSignOffchainMessage`, `useSelectAccount`). The “Framework integration” section tells Vue users to write a `shallowRef` composable with `onMounted`/`onUnmounted` and `client.wallet.subscribe`/`getState`; no Vue package or component is provided — [README: React hooks and Framework integration](https://raw.githubusercontent.com/anza-xyz/kit-plugins/main/packages/kit-plugin-wallet/README.md).
- **Verified — dependency/framework cost of the React path**: the plugin’s npm metadata has peer deps `react ^19.3.1`, `@solana/kit ^8.6.0`, and `@solana/react ^8.6.0`, and dependencies on Wallet Standard UI/registry packages (`@wallet-standard/ui`, `@wallet-standard/app`, `@wallet-standard/base`, `@wallet-standard/features`, `@wallet-standard/ui-features`, `@wallet-standard/ui-registry`) — [npm latest metadata](https://registry.npmjs.org/@solana%2Fkit-plugin-wallet/latest). `@solana/react@8.6.0` itself depends on `@wallet-standard/react` and `@wallet-standard/ui-registry` among others — [npm metadata](https://registry.npmjs.org/@solana%2Freact/latest).
- **Verified — SSR behavior**: all four wallet plugins are safe in a shared server/browser client; on the server `status` stays `pending`, actions throw, and no registry listeners or storage reads occur; React Native is treated like the server because Wallet Standard browser discovery is unavailable — [README: SSR section](https://raw.githubusercontent.com/anza-xyz/kit-plugins/main/packages/kit-plugin-wallet/README.md).
- **Verified — persistence/security policy**: the plugin defaults to `localStorage` persistence and auto-reconnect (configurable); it drops accounts whose `publicKey` does not match `address`, rejects duplicate persisted wallet names, only passes through `data:image/` icons, and verifies offchain/SIWS outputs. It explicitly does **not** verify that the SIWS text inside an offchain message matches caller input — [README: Persistence and Account verification](https://raw.githubusercontent.com/anza-xyz/kit-plugins/main/packages/kit-plugin-wallet/README.md).
- **Verified — chain scoping**: each plugin is bound to a single chain (`chain: 'solana:mainnet'` in examples), and `whenReady()` exists mainly for runtime client/chain swaps — [README: Quick start and `whenReady()`](https://raw.githubusercontent.com/anza-xyz/kit-plugins/main/packages/kit-plugin-wallet/README.md).
- **Verified — vue-solana already has its own wallet layer**: the repository implements Wallet Standard discovery/adapter code, Android MWA registration/session code, iOS browser wallet adapter/deep-link/callback code, and a `makeConnectExclusive` wallet registry — [wallet-standard source](https://github.com/vue-solana/vue-solana/tree/main/packages/core/src/wallet-standard), [mobile-wallet source](https://github.com/vue-solana/vue-solana/tree/main/packages/core/src/mobile-wallet), [ios-wallet source](https://github.com/vue-solana/vue-solana/tree/main/packages/core/src/ios-wallet), [wallet-registry.ts](https://github.com/vue-solana/vue-solana/blob/main/packages/vue/src/plugin/wallet-registry.ts).
- **Verified — official MWA stack exists separately**: `@solana-mobile/mobile-wallet-adapter-protocol-kit@3.0.2` has a peer on `@solana/kit ^8.0.0`, and `@solana-mobile/wallet-standard-mobile@0.7.1` is a separate Wallet Standard wallet for MWA apps — [MWA Kit npm](https://registry.npmjs.org/@solana-mobile%2Fmobile-wallet-adapter-protocol-kit/latest), [wallet-standard-mobile npm](https://registry.npmjs.org/@solana-mobile%2Fwallet-standard-mobile/latest), [MWA README](https://github.com/solana-mobile/mobile-wallet-adapter#readme).

### Inferences

- The official direction is **headless wallet state + framework adapters**, not a cross-framework UI kit. Vue Solana’s composables already match that architecture; a UI package should consume the existing context rather than replace it with `client.wallet`.
- Adding `kit-plugin-wallet` on top of vue-solana’s current registry would create two discovery lists, two selected-account states, two reconnect policies, and two payer/identity mappings. That is a real conflict, not merely duplicate dependency weight.
- Replacing vue-solana’s custom discovery layer with the plugin would lose or require reimplementation of the project’s bespoke MWA session workarounds and iOS browser deep-link/callback support; the plugin’s README explicitly scopes browser Wallet Standard discovery and treats React Native/server as inert — inferred from the README and the repository’s mobile/iOS source layout.
- The plugin is useful as a **reference implementation** for reconnect warm-up gating, account verification, and SSR-safe stubs; those semantics are worth translating into Vue composables without importing the plugin.

### Gaps

- No source directly tests `kit-plugin-wallet` together with `@solana-mobile/wallet-standard-mobile` or a custom iOS adapter; “conflict” is inferred from duplicated state/discovery responsibilities and differing platform scopes.
- No Vue binding, Vue package, or official component roadmap was found in the inspected Kit/plugin repositories; absence is from README/source inspection, not a maintainer statement that Vue is excluded forever.
- Exact publish timestamps for plugin 0.23.0 are from npm’s version `time` field; GitHub releases were not checked for the plugin repo in this pass.

## 3. Which Vue/Nuxt UI ecosystems matter, and should a Vue Solana component library integrate with one or stay unstyled/headless?

### Takeaway

The relevant Vue/Nuxt UI ecosystems in 2026 are **Nuxt UI** (module/Vite plugin, Tailwind + Reka UI), **Reka UI** (unstyled accessible primitives), **shadcn-vue** (copy-and-customize component source), and the large styled frameworks **Vuetify** and **Quasar**; Headless UI Vue is still heavily downloaded but its npm release is stale. Verified adoption/star data strongly favors headless/primitive-friendly architecture. A Vue Solana UI package should be headless by default with optional Nuxt UI/shadcn-vue recipes, not a hard dependency on one design system — this is an inference from ecosystem shape, not a stated community requirement.

### Cited Findings

- **Verified — Nuxt UI adoption and positioning**: `@nuxt/ui@4.13.1` was published 2026-11-23 and had **1,087,823 weekly downloads** (2026-11-17..23); `nuxt/ui` had 7,101 stars and was pushed 2026-11-25 — [npm registry](https://registry.npmjs.org/@nuxt%2Fui), [weekly downloads](https://api.npmjs.org/downloads/point/last-week/@nuxt%2Fui), [GitHub API](https://api.github.com/repos/nuxt/ui). Its README describes “accessible, typed Vue components built on Reka UI, Tailwind CSS and Tailwind Variants”, working as a Nuxt module and a Vite plugin in plain Vue — [Nuxt UI v4 README](https://raw.githubusercontent.com/nuxt/ui/v4/README.md).

Previously Radix Vue” — [npm registry](https://registry.npmjs.org/reka-ui), [weekly downloads](https://api.npmjs.org/downloads/point/last-week/reka-ui), [GitHub API](https://api.github.com/repos/unovue/reka-ui). npm describes it as the “Vue port for Radix UI Primitives” — [npm latest](https://registry.npmjs.org/reka-ui/latest).

- **Verified — Headless UI Vue is widely downloaded but stale as a package**: `@headlessui/vue@1.7.23` had **3,575,119 weekly downloads**, but that version was published 2024-09-09; the repo was last pushed 2026-04-13 — [npm registry](https://registry.npmjs.org/@headlessui%2Fvue), [weekly downloads](https://api.npmjs.org/downloads/point/last-week/@headlessui%2Fvue), [GitHub API](https://api.github.com/repos/tailwindlabs/headlessui). ### Inferences

- A styled Vue Solana component package that hard-depends on Nuxt UI or Vuetify would exclude apps using shadcn-vue/Reka UI/Quasar and would put vue-solana in the business of maintaining visual tokens.
- The low-friction shape is: headless composable-driven components (slot-based, no CSS contract), plus small optional integrations/recipe packages for Nuxt UI and shadcn-vue. Nuxt auto-imports would make a Nuxt-specific layer especially natural, but the core components should remain framework-agnostic Vue.
- Reown AppKit is the strongest full-UI competitor for Vue/Nuxt + Solana, but its cloud/project-ID model, dual Solana SDK dependency graph, and commercial license make an official lightweight, local-first Vue Solana UI layer plausibly differentiated.
- If vue-solana ships UI, it should not try to replicate AppKit’s swaps/on-ramp/email-wallet surface; the differentiated scope would be wallet connect/account/mobile/transaction status UX wired to vue-solana’s existing headless state.

### Gaps

- No direct developer preference data or Vue ecosystem survey was found; “expected to be headless” is inferred from package positioning and adoption, not user statements.
- No benchmark was gathered comparing rendered bundle size of AppKit Vue/Solana, Nuxt UI components, or a hypothetical vue-solana UI package.
- No evidence was collected about locale/i18n conventions across Vuetify/Quasar/Nuxt UI beyond their general component positioning.

## 4. Are there existing Vue Solana UI/component packages, and how active/popular are they?

### Takeaway

No active, maintained Vue Solana UI library was found. The old official-ish `@solana/wallet-adapter-vue` and `@solana/wallet-adapter-vue-ui` packages are from 2022 with tiny traffic; `solana-wallets-vue` is the only reasonably known Vue wallet package but was last released 2025-02-10 and depends on web3.js v1. Vue Solana itself has no `@vue-solana/ui` package. The meaningful “Vue + Solana UI” competitor in 2026 is Reown AppKit’s Vue/Nuxt SDK, not a Vue-native Solana community kit.

- **Verified — current vue-solana adoption baseline**: `@vue-solana/core`, `@vue-solana/vue`, and `@vue-solana/nuxt` were all at 4.5.1 in the npm search snapshot, with weekly downloads around 1,342/1,364/1,346 respectively — [npm search “vue solana”](https://registry.npmjs.org/-/v1/search?text=vue%20solana&size=25). A direct `@vue-solana/vue` check showed **1,079 weekly downloads** on the point API — [weekly downloads](https://api.npmjs.org/downloads/point/last-week/@vue-solana%2Fvue). The difference is due to different npm endpoints/snapshots and should not be treated as unique-user growth.
- **Verified — GitHub search results are mostly demos/forks**: repository search for “solana vue wallet” returned 16 results; only `lorisleiva/solana-wallets-vue` had meaningful stars (195), while the next results had 7, 5, 2, 1 or 0 stars. “vue solana ui” returned three 0-star demo projects — [GitHub repo search 1](https://api.github.com/search/repositories?q=solana%20vue%20wallet%20in%3Aname%2Cdescription&sort=stars&per_page=15), [GitHub repo search 2](https://api.github.com/search/repositories?q=vue%20solana%20ui%20in%3Aname%2Cdescription&sort=stars&per_page=15).

- **Verified — AppKit is active in Vue/Nuxt**: AppKit has official Vue and Nuxt installation docs and a Vue Solana adapter path — [AppKit Vue docs](https://docs.reown.com/appkit/vue/core/installation). Its repo had 5,463 stars and was pushed 2026-11-19 — [GitHub API](https://api.github.com/repos/reown-com/appkit).

### Inferences

- There is no crowded Vue-native UI niche to defend; if vue-solana ships UI, it would be defining the category rather than competing with an active community package.
- The old Vue wallet packages are weak substitutes: web3.js v1, wallet-only scope, no Kit/MWA/iOS/deep-link architecture, and negligible maintenance. Their download numbers are not evidence of a healthy ecosystem.
- The real competitive pressure on a future UI package comes from cross-chain/vendored solutions like AppKit that already provide polished Vue/Nuxt modals; vue-solana’s differentiation would be Kit-first, local-first, SSR-safe, and Vue-idiomatic.
- Given vue-solana packages are around 1k weekly downloads, a UI package is unlikely to gain adoption purely from branding; it would need to solve mobile handoff and SSR/hydration better than the React-ported patterns.

### Gaps

- npm/GitHub search can miss private, unindexed, or non-English-registry packages; no Chinese npm registry or community forum survey was performed.
- No evidence was found of a maintained Vue component kit specifically for Solana transaction status/toasts; absence is based on npm/GitHub searches, not an exhaustive package-index crawl.
- `apps/docs` uses the published `@vue-solana/nuxt` package, but this research did not inspect docs-site components for internal-only UI patterns that could be promoted to a package.

## 5. What user complaints recur about wallet modals, mobile handoff, a11y, SSR/hydration, and bundle size?

### Takeaway

Verified recurring complaints in `anza-xyz/wallet-adapter` are SSR/hydration mismatches, wallet-not-detected/stuck connect states, mobile/deep-link failures, CSS override pain, and large bundles. A11y complaints are **not** recurring in that repo; the modal has basic dialog/focus-trap support. These complaints explain where a Vue Solana UI package could genuinely do better if it ships: SSR-safe rendering, deterministic reconnect/connect states, mobile handoff states, and theme integration.

### Cited Findings

- **Verified — SSR/hydration is recurring**: GitHub issue search for `hydration` in `anza-xyz/wallet-adapter` returned 5 issues, including #982 “Hydration failed because the initial UI does not match what was rendered on the server” (2024-06-07, closed) — [search](https://api.github.com/search/issues?q=repo%3Aanza-xyz%2Fwallet-adapter%20is%3Aissue%20hydration&sort=updated&per_page=8), [issue #982](https://github.com/anza-xyz/wallet-adapter/issues/982). Commenters recommend Next `dynamic(..., { ssr: false })` and state: “The state on the client will always be different than the server because the server can’t know about the wallets injected into the browser.” — [issue #982 comments](https://github.com/anza-xyz/wallet-adapter/issues/982). A broader `SSR` search returned 14 issues, including “Unable to build Nuxt 3/Vite project” (#177), “Compatibility with NextJS 13?” (#655), and hydration issue #648 — [SSR search](https://api.github.com/search/issues?q=repo%3Aanza-xyz%2Fwallet-adapter%20is%3Aissue%20SSR&per_page=8), [issue #177](https://github.com/anza-xyz/wallet-adapter/issues/177).
- **Verified — wallet-not-detected/stuck modal states are current**: issue #1111 “Phantom Wallet (Not Detected) does not open install link/redirect” is open, created 2025-07-05, updated 2026-03-24, with 17 comments; clicking the uninstalled wallet only writes localStorage — [issue #1111](https://github.com/anza-xyz/wallet-adapter/issues/1111). Issue #1123 “WalletMultiButton Gets Stuck and Redirects Repeatedly on Uninstalled Wallet Selection” is open, created 2025-09-16, with comments confirming the problem — [issue #1123](https://github.com/anza-xyz/wallet-adapter/issues/1123). Issue #1144 “Phantom wallet does not open when MetaMask extension is also installed” is open, created 2026-02-05 and updated 2026-10-30, with comments describing provider collision — [issue #1144](https://github.com/anza-xyz/wallet-adapter/issues/1144).
- **Verified — browser translation can break wallet selection**: issue #1033 “The React application breaks if you use browser translation” is open, created 2024-10-23 and updated 2026-01-14; the report says connecting via the modal crashes after Chrome translates the page, with multiple “same problem” comments — [issue #1033](https://github.com/anza-xyz/wallet-adapter/issues/1033).
- **Verified — mobile/deep-link handoff is a long-running weakness**: search for `mobile deep link` returned 7 issues, including #385, #988, #409 “Not connecting phantom wallet on mobile devices”, and #562 “Mobile wallet adapter” — [search](https://api.github.com/search/issues?q=repo%3Aanza-xyz%2Fwallet-adapter%20is%3Aissue%20mobile%20deep%20link&per_page=8). Issue #385 was closed as out of scope for Wallet Adapter and redirected to MWA; #988 concerns iOS Safari/Phantom deep links — [issue #385](https://github.com/anza-xyz/wallet-adapter/issues/385), [issue #988](https://github.com/anza-xyz/wallet-adapter/issues/988).
- **Verified — bundle-size complaint is historical but concrete**: issue #356 “Enormous bundle size” reported a 1.3 MB esbuild bundle for a simple script; comments attribute it to importing every adapter and list per-adapter minified sizes of roughly 457 KB–832 KB — [issue #356](https://github.com/anza-xyz/wallet-adapter/issues/356). A `bundle size` search returned 5 issues — [search](https://api.github.com/search/issues?q=repo%3Aanza-xyz%2Fwallet-adapter%20is%3Aissue%20bundle%20size&per_page=8).
- **Verified — CSS/theming override friction**: issue #397 has multiple user workarounds using `!important`, `all: unset`, and Tailwind `@apply` to override `wallet-adapter-*` classes, including the comment “the styling is so disastrous on this thing please fix this garbage” — [issue #397](https://github.com/anza-xyz/wallet-adapter/issues/397).
- **Verified — a11y is not a recurring issue in this repo**: issue search for `accessibility` returned 1 issue (#1119, a SOL-send feature request), and `a11y` returned 1 unrelated TypeScript error (#238) — [accessibility search](https://api.github.com/search/issues?q=repo%3Aanza-xyz%2Fwallet-adapter%20is%3Aissue%20accessibility&per_page=8), [a11y search](https://api.github.com/search/issues?q=repo%3Aanza-xyz%2Fwallet-adapter%20is%3Aissue%20a11y&per_page=8). The UI source nevertheless has dialog semantics, Escape close, Tab focus trap, `aria-expanded`, and `role="menu"` — [WalletModal.tsx](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/WalletModal.tsx), [BaseWalletMultiButton.tsx](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/BaseWalletMultiButton.tsx).
- **Verified — transaction toasts are absent rather than merely unpopular**: a `toast` issue search returned 5 results, none about wallet-adapter UI transaction notifications; the React UI export list contains no toast/notification component — [toast search](https://api.github.com/search/issues?q=repo%3Aanza-xyz%2Fwallet-adapter%20is%3Aissue%20toast&per_page=8), [react-ui index.ts](https://raw.githubusercontent.com/anza-xyz/wallet-adapter/master/packages/ui/react-ui/src/index.ts).

### Inferences

- A “ship UI?” decision should be based on **product gaps not already solved by competitors**: SSR-safe hydration, wallet discovery/reconnect state, mobile handoff/deep-link status, theme integration, and i18n-safe labels. Copying a modal/button alone would duplicate a solved and stale React pattern.
- If the package ships, the strongest architecture is a headless state layer reusing vue-solana composables plus slot-based components and explicit client-only boundaries for Nuxt; optional Nuxt UI/shadcn-vue styling can sit above that.
- The lack of recurring a11y complaints does not mean a11y is solved; the existing implementation’s focus trap only queries buttons and labels are hardcoded, so a Vue package could differentiate with robust dialog semantics, localization, and keyboard/account-switch behavior — inferred from the cited source.
- The bundle-size complaint is old and about wallet adapters rather than the current CSS-only UI package, but it supports the general caution against aggregate wallet imports and static heavy optional dependencies; vue-solana’s existing size invariants remain relevant.

### Gaps

- No direct user complaints were collected from Solana Stack Exchange, Discord, or support tickets; GitHub issues are the only complaint corpus in this pass.
- Issue counts reflect GitHub search text matching and can include false positives or stale/closed reports; they indicate recurring topics, not prevalence across all users.
- No current bundle-size measurement was made for `@solana/wallet-adapter-react-ui` itself, so the #356 figures should be treated as historical context only.
